# 更新日志

## 0.0.10 - 2026-08-14

### 可靠性与清理

- 接通"自动删除已上传文件"：设置页开启后，定时（15 分钟）按保留时长清理已上传批次，避免磁盘满触发整体采集中断。
- 重启恢复改为按 staleAfter 窗口区分：近期"上传中"批次自动回退重试，只有超窗批次才标"待核对"，减少误判。
- 上传失败增加最大重试次数（5 次后转"上传失败"），批次之间加入 200ms 错峰间隔，避免并发连发打崩后端。
- 关键字命中记录截断到 256 字并定期清理 7 天前的记录，控制长挂测下数据库膨胀。

### 体验与可维护

- 设置页"后端地址"可编辑（保存后重启生效），云端迁移无需重装新版本。
- 通道配置新增"编码"下拉（UTF-8 / GB18030 / ASCII），适配中文串口日志。
- 上传队列：查询码展示带项目名关联；"待核对/上传失败"批次支持一键重新上传。
- 项目配置支持导入本地 YAML（与内置配置合并，覆盖或追加关键字方案），无需云端同步。

## 0.0.9 - 2026-08-11

### 演示会优化（依据 2026-08-11 功能演示与讨论会议纪要）

- 串口通道上限从 8 放宽到 64，支持 USB hub 多设备同时挂测。
- "上传云端"开关移到通道配置顶部，未开启时隐藏项目、版本、测试任务、上传人、备注等上传参数。
- 新增滚动诊断日志（`%APPDATA%\LogMaster\logs\collector.log`，单文件 10 MB、保留 5 个备份），记录上传失败原因与重试轨迹；Go 层 panic 堆栈和前端 JS 未捕获异常同样落盘，便于闪退后定位原因；全局设置新增"打开日志目录"入口。
- 上传会话创建失败时透出云端具体原因（如项目不存在、上传人不匹配），不再笼统提示"请重试"。
- 云端上传默认关闭，每个通道不再保留历史配置：重启或换设备后从干净默认值开始，不继承上一台设备的项目/版本/上传人等信息。

## 0.0.8 - 2026-08-09

- 默认日志轮转调整为 30 分钟或 128 MB，减少连续采集产生的上传批次。
- 自动迁移仍使用 5 分钟/32 MB 旧默认值的本地设置。
- 上传队列在文件名前显示当前连续采集会话中的上传位次。

## 0.0.7 - 2026-08-09

- 内置内部云端上传令牌，普通用户无需设置环境变量或接入密钥。
- 保留外部上传令牌覆盖能力，便于联调和后续轮换。

## 0.0.6 - 2026-08-09

### 连续上传会话

- 保存上传配置时创建云端会话并返回查询码，同一串口后续多个批次复用该查询码。
- 上传配置完整时按钮显示“保存上传/通道配置”，上传人为空时禁止创建上传会话。
- 云端不可用时保留本地配置和日志并暂停上传，重试成功后绑定积压批次；程序重启后恢复原会话。
- 未上传历史文件支持只删除记录或同时删除本地文件。

### 验证

- 通过采集端 Go 全量测试、前端测试、生产构建和 Windows Wails 打包。
- 使用 COM24 完成真实日志读取、双批次落盘上传及同查询码聚合查询。

## 0.0.5 - 2026-08-04

### 云端上传

- 适配平台上传字段、Bearer Token 鉴权、GZIP 文件传输及查询码回显。
- 关闭启用上传的串口时，可选择继续上传或停止当前通道上传；停止后重新打开通道可自动续传未完成批次。
- 停止当前通道上传不会影响其他记录仪，已发出的请求仍会等待平台明确响应。

### 验证

- 通过 Go 全量测试、前端测试、前端生产构建及 Windows 桌面端构建。
- 使用 COM24 完成真实日志采集、文件落盘、平台上传、查询码返回和平台解析入库的全链路验收。

## 0.0.3 - 2026-07-30

### 配置与界面

- 增加记录仪和 4G 盒子项目目录、14 类测试任务及联咏项目日志关键字方案。
- 默认日志目录调整为 `D:/LogMaster/LocalLog`，无日志告警调整为 30 分钟，窗口上限调整为 100000 行，本地存储上限调整为 50 GB。
- 上传并发数调整为 5，新通道默认本地保存、默认关闭云端上传。
- 设置页显示正式程序名称、版本、发布日期、公司名称和飞书交流群二维码。
- 新增独立配置维护目录；平台接口和项目版本号未提供的字段明确保留为待配置状态。

## 0.0.2 - 2026-07-26

### 串口通道

- 程序启动和用户手动刷新时扫描 Windows 当前真实存在的串口，不再预先创建固定空通道。
- 每 2 秒监听串口热插拔，端口接入后动态增加通道，移除后自动断开并删除对应通道。
- Windows 扫描以当前存在设备为准，避免把注册表残留端口误报为可用串口。
- 自动清理旧版空通道配置，并将旧默认名称迁移为“串口 COMx”。

### 日志采集与上传

- 修复设备日志没有 CR/LF 换行符时长期滞留内存、无法及时落盘和上传的问题。
- 日志按串口空闲帧边界封口，写入本地日志文件和 SQLite 上传队列。
- 支持通过配置文件设置后端地址、项目、业务版本、鉴权环境变量和 GZIP 上传。
- 上传使用 `multipart/form-data` 调用 `POST /api/logs/upload`，严格校验 HTTP 202、业务状态、上传 ID、任务 ID 和文件数量。

### 桌面界面

- 左侧标题由“设备通道”改为“串口通道”，无可用串口时不显示占位条目。
- 修复采集界面底部大面积无效空白，主工作区自适应填满窗口。
- 点击窗口关闭按钮时显示确认提示；选择“否”取消关闭，选择“是”停止采集、释放串口并彻底退出进程。

### 验证

- COM24 实机完成真实日志采集、日志保存和上传链路测试。
- 实测 COM24 采集中确认关闭后，LogCollector 进程结束，串口可立即被测试程序重新打开。
- Go 全量测试、前端生产构建和 Windows Wails EXE 构建通过。

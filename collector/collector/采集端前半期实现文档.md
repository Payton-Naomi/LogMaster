# 采集端桌面客户端 —— 前半期实现文档

> **覆盖范围**：日志采集 → 本地存储 → 平台上传 三大核心链路
> **技术栈**：Wails v2 + Vue 3（前端） + Go（业务底层）
> **工期参考**：第 1-10 天（第一阶段 + 第二阶段核心）

---

## 一、整体数据流

```
┌──────────┐   串口按行读取    ┌──────────────┐   实时推送(IPC)   ┌──────────────┐
│  串口设备  │ ───────────────→ │  Go 采集引擎  │ ───────────────→ │  Vue 3 前端   │
│  (UART)   │   goroutine/case │  (per device) │   Wails Event   │  日志展示     │
└──────────┘                   └──────┬───────┘                  └──────────────┘
                                      │
                          ┌───────────┼───────────┐
                          │           │           │
                     ▼ 写入本地     ▼ 关键字匹配   ▼ 入上传队列
                  ┌────────┐   ┌──────────┐   ┌──────────┐
                  │ 本地文件 │   │ 异常记录  │   │ SQLite   │
                  │ (按规则  │   │ (内存+DB) │   │ 补传队列  │
                  │  切割)   │   └──────────┘   └────┬─────┘
                  └────────┘                        │
                                                    │ 定时/阈值触发
                                                    ▼
                                              ┌──────────┐
                                              │ GZIP 压缩 │
                                              │ HTTP POST │
                                              └────┬─────┘
                                                   │
                                                   ▼
                                            ┌──────────────┐
                                            │  日志分析平台  │
                                            │  /api/v1/logs │
                                            └──────────────┘
```

**一条日志的完整旅程**：
1. 串口按行读取原始文本
2. 注入时间戳前缀（可选）、设备标签
3. 同时写入三条支路：**前端实时展示**、**本地文件落盘**、**关键字匹配引擎**
4. 关键字命中 → 提取上下文 → 生成异常记录
5. 落盘的文件按切割规则持续追加，切割后的文件进入上传候选
6. 上传调度器定时扫描候选文件 → GZIP 压缩 → HTTP POST 到平台
7. 上传失败则入 SQLite 补传队列，等网络恢复后自动重传

## 二、日志采集模块

### 2.1 核心设计

每个已连接的串口设备在 Go 层启动一个**独立 goroutine** 负责全生命周期：

```
goroutine: deviceCollector(deviceID)
  ├── 打开串口 (go.bug.st/serial)
  ├── 循环按行读取 (bufio.Scanner)
  ├── 每读一行 → 分发到三条管道
  │     ├── chan logLine     → 前端 IPC 推送
  │     ├── chan fileWrite   → 本地文件写入
  │     └── chan keywordMatch → 关键字匹配引擎
  ├── 心跳上报 (每 30s)
  └── 退出：ctx.Done() / 串口读取错误
```

### 2.2 Go 层关键结构

```go
// 设备采集器
type DeviceCollector struct {
    DeviceID    string
    PortName    string          // e.g. "COM3"
    PortConfig  SerialConfig    // 波特率、数据位等
    serialPort  serial.Port     // 打开的串口句柄
    ctx         context.Context
    cancel      context.CancelFunc

    // 三条输出管道
    logChan     chan<- LogLine       // → 前端 + 文件
    exceptionCh chan<- ExceptionHit  // → 异常引擎
}

type LogLine struct {
    DeviceID    string
    DeviceName  string    // 用户自定义名称
    Timestamp   time.Time
    Content     string    // 原始日志行
    LineNumber  uint64    // 自增行号
}
```

### 2.3 串口读取与行解析

```
readLoop():
    scanner := bufio.NewScanner(port)    // 按行扫描
    scanner.Buffer(buf, 1MB)             // 单行最大 1MB 缓冲

    for scanner.Scan() {
        raw := scanner.Text()
        line := LogLine{
            DeviceID:   d.ID,
            DeviceName: d.Name,
            Timestamp:  time.Now(),       // 采集端时间戳
            Content:    raw,
            LineNumber: atomic.AddUint64(&d.lineNum, 1),
        }

        // 注入时间戳前缀（如果配置开启）
        if d.Config.TimestampPrefix {
            line.Content = line.Timestamp.Format("2006-01-02 15:04:05.000") + " " + raw
        }

        // 分发到三条管道（非阻塞发送，避免单路卡死影响采集）
        select {
        case d.logChan <- line:
        default: // 前端消费不过来则丢弃，不阻塞采集
        }
        d.fileWriter.Write(line)
        d.keywordEngine.Match(line)
    }
```

**关键设计决策**：
- **非阻塞发送到前端**：前端渲染慢不应阻塞串口读取，宁可丢弃展示（日志已落盘，不丢数据）
- **行号原子自增**：多 goroutine 安全，用于前端跳转定位
- **采集端时间戳注入**：确保即使设备无时间戳，日志也有可追溯的时间信息

### 2.4 Wails IPC 推送到前端

Go 端通过 Wails 的 `Runtime.EventsEmit` 向前端推送：

```go
// Go 侧
func (a *App) startLogStream(deviceID string) {
    ch := a.collectorManager.GetChannel(deviceID)
    for line := range ch {
        runtime.EventsEmit(a.ctx, "log:"+deviceID, line)
    }
}
```

Vue 3 侧接收：

```typescript
// Vue 3 侧
import { EventsOn } from '@/wailsjs/runtime/runtime'

const logLines = ref<LogLine[]>([])
const MAX_BUFFER = 5000  // 前端最多缓存 5000 行

EventsOn('log:' + deviceId, (line: LogLine) => {
  logLines.value.push(line)
  // 环形缓冲，超出裁剪旧数据
  if (logLines.value.length > MAX_BUFFER) {
    logLines.value.splice(0, logLines.value.length - MAX_BUFFER)
  }
})
```

## 三、本地存储模块

### 3.1 文件命名规则

支持模板变量，运行时解析为实际路径：

```
模板：{project}/{task}/{device}_{date}_{time}.log
解析：PRJ001/task_high_temp/DeviceA_20260724_173000.log
```

| 变量 | 含义 | 示例 |
|---|---|---|
| `{project}` | 项目名称 | PRJ001 |
| `{task}` | 任务名称 | task_high_temp |
| `{device}` | 设备自定义名 | DeviceA |
| `{date}` | 日期 | 20260724 |
| `{time}` | 时间 | 173000 |
| `{sn}` | 设备序列号 | SN12345678 |

### 3.2 文件切割策略

采用**双规则 OR 触发**，任一条件满足即切割：

```go
type CutRule struct {
    MaxDuration time.Duration  // 按时间切割，默认 1 小时
    MaxSize     int64          // 按大小切割，默认 50MB
}

func (w *FileWriter) shouldCut() bool {
    elapsed := time.Since(w.currentFileStart)
    size, _ := w.currentFile.Seek(0, io.SeekEnd)  // 注意：SeekEnd 应为 2
    return elapsed >= w.CutRule.MaxDuration || size >= w.CutRule.MaxSize
}
```

切割流程：

```
1. shouldCut() → true
2. Flush 当前文件缓冲区
3. Close 当前文件
4. 将旧文件路径推入上传候选队列
5. 按命名模板生成新文件名
6. Open 新文件，记录 startTime
7. 继续写入
```

### 3.3 实时追加落盘

为保证异常断电不丢数据，采用**每次写入立即 Sync** 策略（可通过配置降级为缓冲写入）：

```go
func (w *FileWriter) Write(line LogLine) error {
    formatted := line.Timestamp.Format("2006-01-02 15:04:05.000") +
                 " [" + line.DeviceName + "] " + line.Content + "\n"

    _, err := w.buf.WriteString(formatted)
    if err != nil {
        return err
    }

    // 即时落盘模式：每条日志都 sync
    if w.Config.SyncEveryLine {
        w.buf.Flush()
        w.file.Sync()   // fsync 到磁盘
    }
    return nil
}
```

**性能权衡**：
- `SyncEveryLine = true`：安全性最高，适合关键测试场景，但磁盘 I/O 压力大
- `SyncEveryLine = false`：每 5 秒或缓冲满 64KB 批量 flush，性能好但有少量丢失风险

## 四、平台上传模块（重点）

### 4.1 总体架构

上传模块是连接本地与平台的关键桥梁，需要同时保证**可靠性**（不丢数据）和**效率**（不阻塞采集）。

│  │  (5min tick)  │   │ (文件>阈值)   │   │ (UI 按钮)    │ │

### 4.2 上传触发策略（三种方式）

#### 方式一：定时触发（主力）

```go
func (m *UploadManager) startScheduler() {
    ticker := time.NewTicker(m.Config.UploadInterval) // 默认 5 分钟
    for {
        select {
        case <-ticker.C:
            m.scanAndEnqueue()
        case <-m.ctx.Done():
            ticker.Stop()
            return
        }
    }
}

func (m *UploadManager) scanAndEnqueue() {
    // 扫描所有已切割完成的文件
    files := m.scanCompletedFiles()
    for _, f := range files {
        if !m.isUploaded(f) {
            m.taskQueue <- UploadTask{FilePath: f, Tags: m.buildTags(f)}
        }
    }
}
```

#### 方式二：大小阈值触发

当单个日志文件超过阈值（如 10MB）时立即触发上传，不等定时器：

```go
func (w *FileWriter) onFileCut(oldFile string) {
    info, _ := os.Stat(oldFile)
    if info.Size() >= w.Config.UploadThreshold {
        w.uploadMgr.EnqueueImmediate(oldFile)  // 插队到队列头部
    } else {
        w.uploadMgr.EnqueueNormal(oldFile)     // 正常排队
    }
}
```

#### 方式三：手动触发

UI 层提供"立即上传"按钮，用户可主动触发所有待上传文件的批量上传。

### 4.3 GZIP 压缩

上传前对文件内容进行 GZIP 压缩，减少传输带宽和耗时：

```go
func compressFile(srcPath string) ([]byte, error) {
    var buf bytes.Buffer
    gw := gzip.NewWriter(&buf)

    f, err := os.Open(srcPath)
    if err != nil {
        return nil, fmt.Errorf("open source: %w", err)
    }
    defer f.Close()

    if _, err := io.Copy(gw, f); err != nil {
        return nil, fmt.Errorf("compress: %w", err)
    }
    if err := gw.Close(); err != nil {
        return nil, fmt.Errorf("close gzip: %w", err)
    }
    return buf.Bytes(), nil
}
```

**为什么先读文件再压缩而不是边读边传？**
- 文件大小可控（经过切割通常 < 50MB），全部读入内存可接受
- 简化重试逻辑：失败后直接从字节数组重发，无需重新读文件
- 避免 HTTP 连接超时期间文件被修改

### 4.4 HTTP 上传协议

#### 请求格式

```
POST /api/v1/logs/upload
Content-Type: multipart/form-data
```

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `file` | file | GZIP 压缩后的日志文件 | logs_deviceA_20260724.gz |
| `project` | string | 项目名称 | PRJ001 |
| `task` | string | 任务名称 | task_high_temp |
| `device_id` | string | 设备唯一标识 | SN12345678 |
| `device_name` | string | 用户自定义设备名 | 设备A-高温箱 |
| `level` | string | 日志级别标记 | info |
| `file_name` | string | 原始文件名（解压后） | PRJ001_task_high_temp_DeviceA_20260724_173000.log |
| `line_count` | int | 日志行数 | 12450 |
| `start_time` | string | 文件首行时间戳 | 2026-07-24T17:30:00+08:00 |
| `end_time` | string | 文件末行时间戳 | 2026-07-24T18:30:00+08:00 |
| `checksum` | string | 文件 MD5（压缩前） | d41d8cd98f00b204e9800998ecf8427e |

#### Go 实现

```go
func (u *Uploader) Upload(ctx context.Context, task UploadTask) error {
    // 1. 读取文件内容
    rawData, err := os.ReadFile(task.FilePath)
    if err != nil {
        return fmt.Errorf("read file: %w", err)
    }

    // 2. 计算原始 MD5
    rawHash := md5.Sum(rawData)

    // 3. GZIP 压缩
    compressed, err := compressBytes(rawData)
    if err != nil {
        return fmt.Errorf("compress: %w", err)
    }

    // 4. 构建 multipart 请求体
    var body bytes.Buffer
    writer := multipart.NewWriter(&body)

    // 文件部分
    part, _ := writer.CreateFormFile("file",
        filepath.Base(task.FilePath)+".gz")
    part.Write(compressed)

    // 标签字段
    tags := task.Tags
    writer.WriteField("project", tags.Project)
    writer.WriteField("task", tags.Task)
    writer.WriteField("device_id", tags.DeviceID)
    writer.WriteField("device_name", tags.DeviceName)
    writer.WriteField("file_name", filepath.Base(task.FilePath))
    writer.WriteField("line_count", strconv.Itoa(tags.LineCount))
    writer.WriteField("start_time", tags.StartTime.Format(time.RFC3339))
    writer.WriteField("end_time", tags.EndTime.Format(time.RFC3339))
    writer.WriteField("checksum", fmt.Sprintf("%x", rawHash))
    writer.Close()

    // 5. 发送 HTTP 请求
    req, err := http.NewRequestWithContext(ctx,
        "POST", u.ServerURL+"/api/v1/logs/upload", &body)
    if err != nil {
        return err
    }
    req.Header.Set("Content-Type", writer.FormDataContentType())

    client := &http.Client{Timeout: 60 * time.Second}
    resp, err := client.Do(req)
    if err != nil {
        return fmt.Errorf("http post: %w", err)
    }
    defer resp.Body.Close()

    if resp.StatusCode != 200 {
        body, _ := io.ReadAll(resp.Body)
        return fmt.Errorf("upload failed: status=%d, body=%s",
            resp.StatusCode, string(body))
    }

    return nil
}
```

### 4.5 补传队列（断网恢复核心机制）

#### 设计思路

上传失败不能丢数据。所有失败的上传任务持久化到 SQLite，网络恢复后自动重试。

#### 数据库表设计

```sql
CREATE TABLE IF NOT EXISTS upload_queue (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    file_path   TEXT NOT NULL,           -- 文件绝对路径
    project     TEXT NOT NULL,
    task        TEXT NOT NULL,
    device_id   TEXT NOT NULL,
    device_name TEXT NOT NULL,
    file_name   TEXT NOT NULL,
    line_count  INTEGER DEFAULT 0,
    start_time  TEXT NOT NULL,
    end_time    TEXT NOT NULL,
    checksum    TEXT NOT NULL,
    status      TEXT DEFAULT 'pending',  -- pending | uploading | done | failed
    retry_count INTEGER DEFAULT 0,
    max_retries INTEGER DEFAULT 5,
    last_error  TEXT,
    created_at  TEXT DEFAULT (datetime('now')),
    updated_at  TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_queue_status ON upload_queue(status);
```

#### 工作流程

```
┌──────────────────────────────────────────────────────┐
│              补传队列生命周期                          │
│                                                      │
│  上传失败 ──→ INSERT INTO upload_queue (status=pending)│
│                     │                                │
│                     ▼                                │
│  Worker 取任务 ──→ UPDATE status=uploading            │
│                     │                                │
│              ┌──────┴──────┐                        │
│              ▼             ▼                         │
│           成功           失败                         │
│              │             │                         │
│              ▼             ▼                         │
│    UPDATE status=done    retry_count++               │
│                          UPDATE status=pending        │
│                          (retry_count < max_retries)  │
│                              │                       │
│                     retry_count >= max_retries        │
│                              │                       │
│                              ▼                       │
│                    UPDATE status=failed               │
│                    用户可手动重试                      │
└──────────────────────────────────────────────────────┘
```

#### Go 实现

```go
// 补传 Worker：持续从队列取待上传任务
func (q *RetryQueue) StartWorker() {
    for {
        select {
        case <-q.ctx.Done():
            return
        default:
        }

        task, err := q.dequeuePending()
        if err != nil {
            time.Sleep(5 * time.Second) // 无任务时等待
            continue
        }

        err = q.uploader.Upload(q.ctx, task.ToUploadTask())
        if err != nil {
            q.markFailed(task.ID, err)
            task.RetryCount++
            if task.RetryCount < task.MaxRetries {
                q.resetPending(task.ID)
            }
        } else {
            q.markDone(task.ID)
        }
    }
}

// 网络恢复后自动触发全量补传
func (m *UploadManager) onNetworkRestored() {
    log.Println("[Upload] 网络恢复，开始补传...")
    count, _ := m.retryQueue.GetPendingCount()
    log.Printf("[Upload] 待补传任务数: %d", count)
    // Worker 已经在跑，会自动消费 pending 任务
}
```

### 4.6 网络状态检测

// 定时检测网络可达性
func (m *UploadManager) startNetworkMonitor() {
    ticker := time.NewTicker(30 * time.Second)
    wasOffline := false

    for range ticker.C {
        online := m.checkConnectivity() // 对平台地址发 HEAD 请求
        if online && wasOffline {
            m.onNetworkRestored()
        }
        wasOffline = !online

    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)

        return false

### 4.7 并发控制与错峰调度

```go
type UploadManager struct {
    taskQueue   chan UploadTask        // 缓冲队列，容量 100
    maxWorkers  int                    // 最大并发上传数，默认 2
    workerWg    sync.WaitGroup
}

func (m *UploadManager) StartWorkers() {
    for i := 0; i < m.maxWorkers; i++ {
        m.workerWg.Add(1)
        go m.worker(i)
    }
}

func (m *UploadManager) worker(id int) {
    defer m.workerWg.Done()
    for task := range m.taskQueue {
        // 上传前检查网络状态
        if !m.isOnline.Load() {
            // 网络不可用，任务重回队列（由补传队列处理）
            m.retryQueue.Enqueue(task)
            continue
        }

        err := m.uploader.Upload(m.ctx, task)
        if err != nil {
            log.Printf("[Worker-%d] 上传失败: %v", id, err)
            m.retryQueue.Enqueue(task) // 失败入补传队列
        } else {
            log.Printf("[Worker-%d] 上传成功: %s", id, task.FilePath)
            m.markFileUploaded(task.FilePath)
        }

        // 请求间隔控制，避免冲击后端
        time.Sleep(500 * time.Millisecond)
    }
}
```

**并发控制关键点**：
- 最大 2 个并发上传 Worker，避免带宽拥堵
- 每个 Worker 处理完一个任务后间隔 500ms，给后端喘息空间
- 上传失败直接入补传队列，不阻塞其他任务

通过 Wails IPC 定期推送到前端，在状态栏和上传面板实时展示。

## 五、模块间数据流整合

### 5.1 启动采集的完整时序

```
用户点击"开始采集"
        │
        ▼
┌─ Go: App.StartCollecting(deviceID) ──────────────────────┐
│                                                          │
│  1. 从配置加载设备参数（波特率等）                          │
│  2. 打开串口                                               │
│  3. 创建 DeviceCollector                                   │
│  4. startLogStream(deviceID)   ← 启动 IPC 推送             │
│  5. FileWriter.Open(namingTemplate) ← 打开本地文件          │
│  6. KeywordEngine.LoadRules(taskID) ← 加载关键字规则        │
│  7. go collector.readLoop()    ← 启动读取循环              │
│  8. 状态更新 → 前端展示"采集中"                             │
│                                                          │
└──────────────────────────────────────────────────────────┘
        │
        ▼
  readLoop 持续运行
        │
        ├── 每行日志 → logChan → IPC → Vue 前端实时展示
        ├── 每行日志 → FileWriter.Write → 本地文件追加
        ├── 每行日志 → KeywordEngine.Match → 异常记录
        ├── FileWriter.shouldCut() → 切割文件 → 推入上传候选
        └── UploadManager.scanAndEnqueue() → 定时上传
```

### 5.2 停止采集的完整时序

```
用户点击"停止采集"
        │
        ▼
┌─ Go: App.StopCollecting(deviceID) ───────────────────────┐
│  1. collector.cancel()      ← 取消 context，readLoop 退出 │
│  2. 关闭串口端口                                           │
│  3. close(logChan)          ← 关闭日志管道                 │
│  4. FileWriter.Flush()      ← 确保最后的数据落盘           │
│  5. FileWriter.Close()      ← 关闭文件，触发上传候选        │
│  6. 清理 goroutine                                         │
│  7. 状态更新 → 前端展示"已停止"                             │
└──────────────────────────────────────────────────────────┘
```

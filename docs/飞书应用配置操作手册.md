# LogMaster 飞书应用配置操作手册

本手册说明如何配置飞书开放平台应用，使 LogMaster 平台具备飞书登录、用户信息获取（含邮箱、职位）与解析完成通知能力。

## 1. 概览：代码用到的飞书能力

| 能力 | 飞书接口 | 对应权限 | 用途 | 必需性 |
| --- | --- | --- | --- | --- |
| 登录 | `POST /open-apis/authen/v2/oauth/token` | 无需额外权限（应用可用即可） | 用授权码换取用户令牌 | 必开 |
| 用户信息 | `GET /open-apis/authen/v1/user_info` | 见下方权限说明 | 获取姓名、邮箱、职位 | 必开 |
| 应用令牌 | `POST /open-apis/auth/v3/tenant_access_token/internal` | 无需额外权限 | 发通知前换取应用身份 | 通知功能时必开 |
| 发送通知 | `POST /open-apis/im/v1/messages` | `im:message` 系列 | 解析完成后向上传人推送消息 | 可选 |

对应代码位置：

- `internal/auth/feishu.go` — 登录与用户信息获取
- `internal/logservice/feishu_notification.go` — 解析完成通知

## 2. 前置条件

- 拥有飞书企业管理后台权限（或能联系企业管理员审批权限与发布）。
- 已确定 LogMaster 服务对外可访问的地址（登录回调需要公网可达，或与企业网络环境匹配）。

## 3. 创建 / 选择应用

1. 访问 [飞书开放平台](https://open.feishu.cn/app)（需用企业账号登录）。
2. 点击「创建企业自建应用」（如果项目已有应用，直接点进现有应用跳过本节）。
3. 填写：
   - **应用名称**：例如 `LogMaster 日志分析平台`
   - **应用描述**：软测日志分析平台
   - **应用图标**：可选，可后补
4. 创建完成后进入应用管理后台，记下两个值（配置服务端环境变量要用）：
   - **App ID**（形如 `cli_xxxxxxxxxxxx`）
   - **App Secret**（点击「凭证与基础信息」→ 查看，可重置）

## 4. 开通权限

在应用管理后台左侧菜单进入 **「权限管理」**，在搜索框中逐个搜索并开通以下权限：

### 4.1 用户信息相关（登录必须）

| 权限标识 | 说明 | 用途 |
| --- | --- | --- |
| `contact:user.base:readonly` | 获取用户基本信息 | 姓名、头像、职位（job_title） |
| `contact:user.email:readonly` | 获取用户邮箱 | 上传人邮箱展示、重名区分 |

> 说明：
> - `contact:user.base:readonly` 对应 `user_info` 接口返回姓名、职位等基础字段。
> - `contact:user.email:readonly` 是邮箱字段（`email`）的读取权限，**如果不开，接口返回的 email 为空字符串**，平台里的邮箱展示功能将看不到邮箱。
> - 如果登录后连姓名都是空或接口报权限错误，按错误信息补开对应权限（例如个别租户还需要 `contact:user.employee_id:readonly`）。

### 4.2 消息通知相关（可选，不做飞书通知可跳过）

| 权限标识 | 说明 | 用途 |
| --- | --- | --- |
| `im:message` | 获取与发送单聊消息 | 以机器人身份发送解析完成通知 |
| `im:message:send_as_bot` | 以应用身份发消息 | 同上（部分版本仅需此项） |

> 若只开通 `im:message:send_as_bot` 发送失败，补开 `im:message` 再试。

### 4.3 权限生效前提：发布版本

飞书自建应用的权限**必须发布后才会在正式环境生效**。开通权限后：

1. 左侧菜单进入 **「版本管理与发布」**。
2. 点击「创建版本」：
   - **版本号**：如 `1.0.0`
   - **可用范围**：选择「全员」或指定部门（建议先指定测试部门灰度）
   - **权限说明**：填"开通飞书登录与日志通知"
3. 提交发布，等待企业管理员审核通过。

> 提示：企业自建应用发布审核一般由企业管理员在管理后台处理，如需加速请联系管理员。

## 5. 配置登录回调地址

在应用管理后台左侧菜单 **「安全设置」→「重定向 URL」**（部分版本路径为「安全设置」→「回调地址」）：

1. 点击「添加」。
2. 填入 LogMaster 的飞书回调地址，格式必须为：
   ```
   http(s)://<你的服务地址>/api/auth/callback
   ```
   例如本地开发：`http://localhost:8080/api/auth/callback`
   例如服务器：`https://logmaster.example.com/api/auth/callback`
3. 保存。

> 该地址必须与服务端环境变量 `FEISHU_REDIRECT_URI` **完全一致**，否则登录时会报 redirect_uri 不匹配。

## 6. 服务端环境变量配置

在 LogMaster 服务的环境配置中设置：

| 环境变量 | 必填 | 说明 | 示例 |
| --- | --- | --- | --- |
| `FEISHU_APP_ID` | 是 | 飞书应用 App ID | `cli_aac4efb073789bd0` |
| `FEISHU_APP_SECRET` | 是 | 飞书应用 App Secret | `xxxxxxxxxxxxxxxx` |
| `FEISHU_REDIRECT_URI` | 否 | 回调地址，默认 `http://localhost:8080/api/auth/callback` | `https://logmaster.example.com/api/auth/callback` |

### 6.1 角色自动分配（可选）

| 环境变量 | 说明 | 示例 |
| --- | --- | --- |
| `FEISHU_ROLE_TITLE_RULES` | 职位关键词到角色的映射，分号分隔，格式 `关键词=角色`，角色支持 `developer/admin/user` | `测试主管=admin;研发=developer` |
| `FEISHU_SUPER_ADMIN_OPEN_IDS` | 超级管理员 open_id 列表，逗号分隔；仅此配置能自动授予超管 | `ou_xxx,ou_yyy` |
| `FEISHU_SUPER_ADMIN_NAMES` | 超级管理员姓名列表，逗号分隔（兜底用） | `刘欣彤` |

> 超级管理员也可登录后在系统内手动授予（角色来源为 manual）。

### 6.2 通知功能（可选）

| 环境变量 | 说明 |
| --- | --- |
| `PUBLIC_BASE_URL` | 平台公网访问地址，用于通知消息里的结果链接，如 `https://logmaster.example.com` |
| `AGENT_ANALYSIS_URL` / `AGENT_ANALYSIS_TOKEN` | Agent 分析地址与令牌（通知依赖解析完成，与飞书无关） |

## 7. 验证步骤

### 7.1 验证登录

1. 启动服务后访问 `http://<服务地址>`。
2. 点击「飞书登录」，应跳转到飞书授权页。
3. 授权后应回到平台首页，右上角显示当前用户姓名。

### 7.2 验证用户信息（邮箱、职位）

1. 登录后访问（或前端用户信息接口）：
   ```
   GET /api/user/info
   ```
2. 正常返回应包含：
   ```json
   {
     "name": "王占赢",
     "email": "wangzy@company.com",
     "job_title": "测试工程师"
   }
   ```
3. 如果 `email` 为空：
   - 确认已开通 `contact:user.email:readonly` 且已发布版本；
   - 确认该用户飞书资料里填写了邮箱；
   - 权限开通后需重新走一遍登录（旧 token 不生效）。

### 7.3 验证通知（可选）

1. 配置 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` 后重启服务（日志会提示 Feishu analysis notifications enabled）。
2. 上传一份日志并等待解析完成。
3. 上传人应收到飞书机器人消息「日志分析完成」。

## 8. 常见问题排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 登录跳转报 `redirect_uri` 不匹配 | 回调地址与平台配置不一致 | 核对平台「重定向 URL」与 `FEISHU_REDIRECT_URI` 完全一致 |
| 登录报 `app_ticket` / 无权限错误 | 应用未发布或权限未审核通过 | 检查「版本管理与发布」状态，重新发布 |
| `email` 为空 | 未开 `contact:user.email:readonly`；或用户无邮箱；或权限未生效 | 开通权限 → 发布 → 重新登录 |
| `job_title` 为空 | 未开 `contact:user.base:readonly`；或用户无职位字段 | 同上 |
| 通知收不到 | `im:message` 权限不足；应用机器人未启用；用户未与机器人建立会话 | 补开 `im:message`，确认应用内「机器人」功能已启用 |
| 首次登录后不是管理员 | 第一个登录用户自动成为超管；若已有超管则按角色规则分配 | 用 `FEISHU_SUPER_ADMIN_OPEN_IDS` 配置指定超管 |
| 权限开通后仍异常 | 权限变更需重新登录获取新 token | 退出重新登录；必要时重启服务 |

## 9. 相关代码位置

- 飞书登录与用户信息：`internal/auth/feishu.go`、`internal/auth/service.go`
- 解析完成通知：`internal/logservice/feishu_notification.go`
- 环境变量读取：`internal/config/config.go`、`.env.example`

# LogMaster 开发协作流程与联调规范

## 1. 项目分支管理规范

项目采用 Git 分支管理模式：

```
main
 │
 └── develop
      │
      ├── backend
      │
      ├── frontend
      │
      └── collector-client
```

---

## 2. 分支职责说明

| 分支               | 负责人   | 职责               | 是否直接开发   |
| ---------------- | ----- | ---------------- | -------- |
| main             | 项目负责人 | 稳定发布版本           | ❌ 禁止直接开发 |
| develop          | 全员集成  | 功能合并测试           | ❌ 不直接写功能 |
| backend          | 后端开发  | 服务端 API、数据库、业务逻辑 | ✅        |
| frontend         | 前端开发  | Web 页面、交互、接口调用   | ✅        |
| collector-client | 采集端开发 | 日志采集、设备通信、客户端程序  | ✅        |

---

# 3. 开发人员日常流程

## 3.1 后端开发流程

负责人：

backend 开发人员

进入分支：

```bash
git checkout backend
```

同步最新代码：

```bash
git pull origin backend
```

开发：

包括：

* API 接口
* 数据库设计
* 数据处理逻辑
* 用户权限
* 服务端功能

提交：

```bash
git add .
git commit -m "backend: 完成功能描述"
```

推送：

```bash
git push origin backend
```

提交完成后：

创建 Pull Request：

```
backend
    ↓
develop
```

等待测试通过后合并。

# 6. 联调流程

## 6.1 联调环境

所有功能进入：

```
develop
```

后开始联调。

联调环境：

```
develop
 |
 +-- backend 服务
 |
 +-- frontend 页面
 |
 +-- collector 客户端
```

---

# 6.2 联调步骤

## 第一步：启动后端

后端：

启动服务：

```bash
go run main.go
```

确认：

* 服务正常启动
* 数据库连接正常
* API 可访问

---

## 第二步：启动前端

安装：

```bash
npm install
```

运行：

```bash
npm run dev
```

确认：

* 页面加载正常
* API 请求成功

---

## 第三步：启动采集端

运行：

```
collector-client
```

确认：

* 设备连接正常
* 日志采集正常
* 数据上传成功

---

# 8. Bug 修复流程

发现 Bug：

不要直接修改 main。

流程：

```
发现问题
    |
    |
创建修复分支
    |
    |
提交测试
    |
    |
合并 develop
    |
    |
发布 main
```

例如：

```bash
git checkout develop

git checkout -b fix-upload-error
```

修复：

```bash
git add .
git commit -m "fix: resolve upload failure"
git push
```

提交：

```
fix-upload-error
        ↓
develop
```

---

# 9. 发布流程

当 develop 联调完成：

## 第一步

确认：

```
develop
```

稳定。

测试：

* 功能测试
* 性能测试
* 部署测试

---

## 第二步

合并：

```
develop
      ↓
main
```

执行：

```bash
git checkout main

git pull

git merge develop

git push
```

# 10. 发布版本管理

创建版本：

例如：

```
v0.1.0
```

执行：

```bash
git tag v0.1.0

git push origin v0.1.0
```

版本规则：

```
v主版本.次版本.修订版本
```

例如：

```
v1.0.0
正式版本

v1.1.0
新增功能

v1.1.1
Bug修复
```

---

# 11. 开发结束后的维护流程

项目完成后：

## main

作为正式版本：

```
main
```

只接受：

* 发布版本
* Bug修复
* 紧急更新

---

## develop

作为持续开发：

```
develop
```

用于：

* 新功能开发
* 下一版本准备

---

## 开发人员退出项目

处理：

1. 提交未完成代码

2. 创建说明文档

3. 更新 README

4. 移交分支权限

---

# 12. 禁止事项

禁止：

❌ 直接 push main

❌ 强制 push：

```bash
git push --force
```

❌ 提交敏感文件：

```
.env
密码
Token
数据库账号
```

❌ 未测试直接合并 develop

---

# 13. 项目最终结构

稳定后：

```
main
 |
 |
develop
 |
 +-------------+
 |             |

 |

```


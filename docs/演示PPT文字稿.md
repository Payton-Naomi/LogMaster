## P3 背景与痛点：设备日志排查为什么难

- **日志散落**：串口日志靠人工拷贝、U 盘导出，易丢失、难追溯
- **排查靠经验**：手工 grep 搜关键字，新人无从下手，结论因人而异
- **发现滞后**：异常发生数天后才被翻到，错过复现窗口
- **协作低效**：分析结果靠聊天工具截图传递，经验无法沉淀
- **体量大增长快**：单设备日志可达 GB 级，人工逐行查看不现实

## P4 解决方案总览

**一句话定位：从"串口数据"到"根因结论"的全自动流水线**

串口实时采集 → 本地落盘 · 断网续传 → 自动上传 → 规则解析 → AI 根因分析 → 飞书告警 / 可视化看板

- 桌面采集端：无人值守，插上串口即采集
- 服务端：Go + PostgreSQL，异步流水线处理
- Web 控制台：Vue 3 单页应用，11 个功能页面
- 飞书生态：扫码登录 + 实时告警

## P5 系统架构

**三层架构，一套闭环**

| 层 | 技术 | 职责 |
|---|---|---|
| 采集端 | Go + Wails 桌面应用 | 串口采集、本地缓存、断点续传 |
| 服务端 | Go + PostgreSQL | 上传 / 解析 / AI / 通知四大异步队列 |
| 前端 | Vue 3 + SSE 实时推送 | 上传、检索、看板、管理控制台 |

- Docker Compose 一键部署，健康检查就绪
- 全链路异步化：上传即返回，解析分析后台排队执行

## P6 串口日志采集端（桌面应用）

- **实时采集**：串口数据流按帧组包、按行解码，即采即存
- **磁盘即缓冲**：本地分段落盘，长时间采集不丢数据
- **断网自动续传**：五状态机管理（待传 / 上传中 / 已传 / 失败 / 拒绝）
- **失败智能分类**：可重试 / 结果未知 / 拒绝 / 暂停 / 拆分，区别处理
- **崩溃恢复**：进程重启后自动恢复现场，续传未完成数据
- **本地自治**：关键字本地命中检测，已传数据自动过期清理

【讲稿】强调"无人值守"：设备挂在产线或实验室，采集端装在一台工控机上就完成了部署。

## P7 日志上传与管理

- **7 种格式**：LOG / TXT / OUT / CSV / ZIP / GZ / TGZ / TAR.GZ
- **加密 ZIP**：密码服务端托管，自动解压
- **大文件友好**：分片上传 + 断点续传（上传会话机制）
- **不覆盖**：同名文件自动追加时间戳
- **可追溯**：项目 / 版本 / 大小 / 时间 / 上传人全记录
- **可管控**：上传容量配额与归档策略

【讲稿】如果现场演示：上传一个含加密 ZIP 的多文件批次，展示任务列表立即出现排队任务。

## P8 规则引擎：把专家经验变成平台能力

- **关键字规则库**：分类 / 级别 / 优先级 / 启停，支持 `|` 多关键字、大小写不敏感
- **命中留证**：自动保留前 50 行 + 命中行 + 后 50 行
- **关联分析**：自动识别 SD 卡、I/O、文件系统、写盘、看门狗、崩溃等可能原因
- **测试场景库**：场景 / 检查项 / 关键字 / 严重程度 / 判定方式，可复用
- **规则批量管理与导入**，团队共享一套经验

【讲稿】这一页的核心卖点：老工程师的经验从"在他脑子里"变成"在平台里"，新人直接复用。

## P9 AI 智能分析

- **LLM 根因分析**：对命中日志自动输出"可能原因 + 处理建议"
- **任务队列保障**：租约机制 + 崩溃恢复，AI 任务不丢失、不重复
- **安全防护**：日志内容与模型指令严格隔离，防提示注入攻击
- **灵活配置**：管理端可配置 AI 分析设置，模型可切换

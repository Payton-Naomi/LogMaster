# 后端修改

> 本文档按时间倒序记录后端改动，供前端对接。每个日期段落标题形如「816 调整」「815 调整」。最新改动在最上方。

## 818 调整（2026-08-18）

### 采集端上传身份校验

采集端创建上传会话必须提交 `uploader_email`。后端先调用飞书通讯录 `contact/v3/users/batch_get_id` 校验邮箱是否属于当前企业且账号有效，再获取姓名和 `open_id`，并写入/更新 `users` 表及上传会话身份字段；`uploader_name` 为可选交叉校验字段。邮箱不属于企业、账号无效或姓名不匹配返回 HTTP 400。数据库迁移 `026_collector_identity_and_errors.sql` 增加会话身份字段。完成后需重启后端使迁移自动执行。

AI 分析完成后会写入 `logmaster_api.ai_usage` 记录 token 用量。新增迁移 `027_ai_usage_permissions.sql`，补齐该表及 `ai_usage_id_seq` 的数据库权限；重启后端执行迁移即可修复 `SQLSTATE 42501` 权限错误。

AI 命中日志采样不再简单取前 50 条，而是按规则/关键词分组轮询，尽量覆盖不同类型的命中；重复命中不会独占整个 AI 输入样本。

### 819 调整：超级管理员动态 AI 配置

超级管理员可通过现有 `GET/PUT /api/admin/ai-analysis-settings` 修改 `llm_api_base_url`、`llm_model`、`llm_timeout_seconds`、`llm_max_matches`、`llm_max_input_bytes`、`max_tokens_per_file` 和 `daily_token_quota`。API Key 仅在 PUT 请求中写入，GET 只返回是否已配置及掩码。新增迁移 `028_dynamic_ai_settings.sql`；API Key 使用部署级 `LOGMASTER_CONFIG_ENCRYPTION_KEY` 加密保存，新 AI 任务读取最新数据库配置，无需重启。

### 二、AI 分析结果接口（前端核心）

#### 2.1 接口

```
GET /api/tasks/{task_id}/agent-results
```

访问要求：飞书 Session（与现有 `results` 接口一致）。URL 未变。

#### 2.2 返回结构

返回一个数组，每条记录是一个「日志文件」的 AI 分析结果：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 1,
      "task_id": "uuid",
      "log_file_id": 3,
      "file_path": "items/1/extracted/system.log",
      "provider": "llm",
      "status": "completed",
      "summary": "本次日志整体运行正常，仅在存储链路出现间歇性 I/O 异常",
      "findings": [
        {
          "category": "storage",
          "severity": "error",
          "root_cause": "存储介质读写超时",
          "evidence": "第 120 行附近连续出现 input/output error",
          "impact": "可能导致录像写入失败并丢失片段",
          "suggestion": "检查 SD 卡健康状态、剩余空间与接触可靠性",
          "confidence": 0.9,
          "line_number": 120,
          "file_path": "items/1/extracted/system.log"
        }
      ],
      "error_message": "",
      "created_at": "2026-08-16T10:00:00Z",
      "updated_at": "2026-08-16T10:00:05Z"
    }
  ]
}
```

#### 2.3 记录级字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 记录 ID |
| `task_id` | string | 任务 ID |
| `log_file_id` | int | 日志文件 ID |
| `file_path` | string | 文件相对路径 |
| `provider` | string | `llm`（直连大模型）或 `http-agent`（外部 Agent） |
| `status` | string | `completed` 或 `failed` |
| `summary` | string | 该文件的 AI 总结 |
| `findings` | array | 该文件的诊断结论列表（见 2.4） |
| `error_message` | string | `status=failed` 时的错误信息 |
| `created_at` / `updated_at` | string | 时间 |

#### 2.4 findings 每项字段（重点：新增了 3 个字段）

| 字段 | 类型 | 是否新增 | 说明 |
|---|---|---|---|
| `category` | string | 否 | 分类：system / camera / gps / storage / sensor / network / recording / unknown |
| `severity` | string | 否 | 级别：warning / error / critical |
| `root_cause` | string | 否 | 可能原因 |
| `evidence` | string | 否 | 证据（引用的命中行或上下文） |
| **`impact`** | string | **是** | **影响**（该问题会造成什么后果） |
| `suggestion` | string | 否 | 建议 |
| `confidence` | number | 否 | 置信度 0~1 |
| **`line_number`** | int | **是** | **关联的原命中行号**（用于定位到结果表格里的某一行） |
| **`file_path`** | string | **是** | **关联的文件路径**（与 `line_number` 一起定位） |

> `line_number` 和 `file_path` 是为了让前端把「AI 解读」精确对应到规则解析结果表格里的某一条命中行。

#### 2.5 异步机制（重要）

AI 分析是**异步任务**：

1. 上传后，关键字规则解析**先同步完成**，`results` 接口立即可查（兜底，永远有结果）。
2. AI 结果在后台生成，**晚几秒到几十秒**才写入。
3. 所以 `agent-results` 接口在解析刚完成时**可能返回空数组**。

前端处理建议：

- 在解析结果页加载时先拉一次 `agent-results`；
- 若为空且任务状态已是 `completed`，可**延迟几秒再拉一次**（或轮询 1~2 次）；
- `provider=llm` 且 `status=completed` 表示 AI 成功，`status=failed` 表示失败（看 `error_message`）。

#### 2.6 AI 分析的输入上下文

AI 分析基于「命中行 + 上下文」。上下文以命中行为中心**对称截取**：命中行前 20 行 + 命中行 + 后 20 行（最多约 41 行），而不是只取命中行之前的日志。

送给模型的上下文中，每一行包含：

| 字段 | 说明 |
| --- | --- |
| `line_number` | 行号 |
| `timestamp` | 该行时间（若有） |
| `level` | 该行级别（error / warning / info / 空） |
| `content` | 该行内容 |
| `is_hit` | 是否为当前命中行（`true` 仅标记本条命中的命中行本身） |

> 说明：若上下文中还包含其它关键字命中，那是一个**独立的**解析结果，不会被合并；在本条命中的上下文里它只是一行普通日志（`is_hit=false`），但会带它自己的 `level`。

### 三、AI 限额（新增）

后端现在对 AI 分析做了**两级限额**，超出后自动降级为「只跑关键字规则」（不影响现有解析结果）。

#### 3.1 两个限额

| 限额 | 含义 | 默认值 |
|---|---|---|
| `max_tokens_per_file` | 单个日志文件允许的 AI 模型最大输出 token 数 | 20000 |
| `daily_token_quota` | 每个用户每天的 AI token 配额 | 1,000,000 |

- 每个文件都可进入 AI 分析；模型输出受 `max_tokens_per_file` 限制。
- 超 `daily_token_quota`：该用户当天后续文件跳过 AI，AI 结果记为 `failed` + `error_message` 提示 quota exceeded。

#### 3.2 管理员配置接口（前端需对接）

```
GET  /api/admin/ai-analysis-settings   # 查询，仅 super_admin
PUT  /api/admin/ai-analysis-settings   # 修改，仅 super_admin
```

`GET` 返回：

```json
{"code":0,"message":"success","data":{"max_tokens_per_file":20000,"daily_token_quota":1000000}}
```

`PUT` 请求体（与返回同结构，`updated_at` 可不传）：

```json
{"max_tokens_per_file":20000,"daily_token_quota":1000000}
```

字段约束：

- `max_tokens_per_file`：整数，1 ~ 1000000
- `daily_token_quota`：整数，`>= 0`，`0` 表示不限制

### 四、前端需要做的三件事

#### 4.1 解析结果页：AI 总结面板

- 数据源：`GET /api/tasks/{task_id}/agent-results`
- 展示：`summary`（文件级总结）+ `findings`（每条展示「可能原因 / 证据 / 影响 / 建议 / 置信度」）
- 处理异步：空结果时延迟重拉或轮询
- 处理失败：`status=failed` 时展示 `error_message` 或不展示 AI 面板

#### 4.2 每条日志「看上下文」旁：AI 解读

- 用 `findings` 里的 `line_number` + `file_path` 与结果表格当前行匹配
- 匹配到 → 在「看上下文」旁显示「AI 解读」入口，点击弹出该行的 AI 结论
- 匹配不到 → 不显示 AI 解读入口（说明该命中没有可用的 AI 分析结果）

#### 4.3 管理页：AI 限额设置

- 对接 `GET/PUT /api/admin/ai-analysis-settings`
- 两个输入框：`max_tokens_per_file`、`daily_token_quota`
- 仅超级管理员可见/可操作（与现有 `upload-capacity` 设置页同一权限级别）
- 表单校验：单文件 token 上限 1~1000000，配额 `>= 0`

### 六、配置项（部署侧，前端一般不需关心，仅供了解）

AI 功能由环境变量控制，未配置时 AI 分析不启用（不影响现有功能）：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `LLM_API_BASE_URL` | 空 | OpenAI 兼容接口地址，空 = 禁用 AI |
| `LLM_API_KEY` | 空 | API Key |
| `LLM_MODEL` | `qwen-plus` | 模型名 |
| `LLM_TIMEOUT_SECONDS` | `120` | 单次分析超时 |
| `LLM_MAX_MATCHES` | `50` | 单次最多送入模型的命中条数，按规则/关键词分组轮询采样 |
| `LLM_MAX_INPUT_BYTES` | `200000` | 单次送入模型的最大输入字节数 |
| `AI_MAX_TOKENS_PER_FILE` | `20000` | 单文件 AI 模型最大输出 token 数（回退默认值） |
| `AI_DAILY_TOKEN_QUOTA` | `1000000` | 每用户每日 token（回退默认值） |

> 限额的最终生效值以管理后台配置为准（存数据库）；环境变量只是「管理员尚未配置时」的回退默认值。

# 后端修改

## 823 调整（2026-08-23）

### AI 持久化队列与独立状态

新增迁移 `042_persistent_ai_queue.sql`。文件级 AI 分析和任务级 AI 总览不再写入容量固定的内存 Channel，而是先写入 PostgreSQL `ai_jobs` 表；AI Worker 使用 `FOR UPDATE SKIP LOCKED` 领取作业，并保存运行令牌、Worker ID、执行次数、90 秒租约和心跳。运行期间每 30 秒续租；服务重启或 Worker 异常后，过期作业自动重新排队，连续中断 3 次后标记为 `failed`。旧执行代次和已取消任务的作业不会被新 Worker 执行。新增 `MAX_AI_WORKERS` 控制单个后端实例的 AI 并发数，默认值为 1；任务级总览只有在同代次文件作业全部结束后才会执行。

`parse_tasks` 新增独立字段 `ai_status` 和 `ai_error_message`，不改变规则解析的 `status`。AI 状态枚举为 `disabled`、`queued`、`running`、`completed`、`partial_failed`、`failed`、`cancelled`。任务列表和任务详情直接返回这两个字段；`GET /api/tasks` 新增可选筛选参数 `ai_status`。整任务 AI 重试、单文件重试和 AI 取消均已切换到持久化队列，接口路径保持不变。

### AI 单文件重试、取消与失败分类

新增迁移 `041_ai_job_controls.sql`，为解析任务增加 `ai_cancel_requested`，并为文件级 AI 结果和任务级 AI 总览增加 `error_code`。新增 `POST /api/tasks/{task_id}/agent-retry/{file_id}`，只删除并重跑指定文件的 AI 结果，不递增解析代次，也不会隐藏其他文件已有结果；文件处理结束后自动刷新任务级 AI 总览。新增 `POST /api/tasks/{task_id}/agent-cancel`，停止该任务尚未执行的 AI 作业，并由 Worker 轮询取消标记、中断正在进行的模型 HTTP 请求；规则解析结果、原始日志和已经完成的 AI 结果均保留。后续调用整任务或单文件 AI 重试时会清除取消标记。

`GET /api/tasks/{task_id}/agent-results` 的文件级结果和任务级总览新增可选字段 `error_code`。失败分类为 `authentication`、`rate_limit`、`quota`、`timeout`、`invalid_response`、`upstream`、`cancelled`、`unknown`，详细中文原因仍由 `error_message` 返回。以上接口只允许有任务访问权限的用户调用，且规则解析必须已经完成。

### 服务端通知中心

在原 `037_notifications.sql` 基础上新增迁移 `043_notification_center_and_downloads.sql`。日志任务完成、失败、取消，AI 完成或失败，异常结果被分配或新增备注时，后端按用户设置写入持久化通知；通知包含可选的 `task_id`、`upload_id` 和 `result_id`。任务及 AI 终态通知使用去重键，服务重启或队列恢复不会重复写入；AI 失败后重试成功仍会产生新的成功通知。通知写入异常不会改变任务或结果操作状态。

通知接口包括：`GET /api/notifications` 分页查询并返回未读数量，`PATCH /api/notifications/{id}/read` 标记单条已读，`POST /api/notifications/read-all` 全部标记已读，`GET /api/notification-settings` 和 `PUT /api/notification-settings` 读取或完整保存七类通知开关。`GET /api/notifications/stream` 提供 SSE 实时通知，支持 `Last-Event-ID` 请求头或 `after_id` 查询参数断点续传；未提供游标时只推送连接建立后的新通知。SSE 每 15 秒发送心跳，并直接轮询 PostgreSQL，因此多后端实例不依赖进程内消息。

### 任务暂停与恢复

新增 `POST /api/tasks/{task_id}/pause` 和 `POST /api/tasks/{task_id}/resume`，并通过迁移 `038_task_pause_resume.sql` 增加 `paused` 状态。排队任务立即暂停，运行任务释放 Worker 租约并在当前文件边界停止；恢复后按原阶段重新进入持久化队列。解析阶段恢复时会重新生成任务结果，避免半完成数据重复。暂停任务仍可取消。

### 任务与项目优先级

新增 `PUT /api/tasks/{task_id}/priority`，任务所有者可为排队或暂停任务设置 `-100~100` 的优先级；新增管理员接口 `PUT /api/admin/projects/{id}/priority`，普通管理员可设置 `-1000~1000` 的项目调度优先级。Worker 按项目优先级与任务优先级之和倒序领取，同分时优先处理更早创建的任务。新增迁移 `039_scheduling_priority.sql`。

### 批量任务与负责人操作

新增 `POST /api/tasks/batch`，请求体包含 `action`（`retry`、`cancel`、`delete`）和最多 100 个 `task_ids`。新增 `PUT /api/results/batch/assignment`，支持一次为最多 500 条异常结果设置或清空负责人。两个接口均逐项执行并返回成功、失败数量以及每项中文结果，不因单项失败回滚整批。

### 任务执行限制

Worker 领取任务时增加单用户和单项目并发约束；准备/解压完成后增加任务文件数量和总字节数约束。新增配置 `MAX_PARSE_PER_USER`（默认 1）、`MAX_PARSE_PER_PROJECT`（默认 2）、`MAX_FILES_PER_PARSE_TASK`（默认 10000）和 `MAX_BYTES_PER_PARSE_TASK`（默认 8GB）。超出任务容量时任务进入 `failed`，并通过中文 `error_message` 和通知返回原因；并发达到上限的任务继续保持 `queued`，等待运行名额。

### 异常操作审计历史

新增迁移 `040_result_audit_history.sql`，由数据库触发器在同一事务内记录异常状态变更、负责人变更和备注新增，保存操作人、旧值、新值和时间。新增 `GET /api/results/{id}/history` 查询当前用户有权访问的审计历史。备注继续采用只追加模式，不开放修改或删除，避免历史内容被覆盖。

### 解析结果和报告下载

新增 `GET /api/tasks/{task_id}/export?format=csv|json|report`。CSV 导出规则命中明细并带 UTF-8 BOM；JSON 数据包包含任务、文件、规则结果、文件级 AI 结果和任务级 AI 总览；`report` 返回 Markdown 分析报告。接口复用任务访问权限，不新增数据库迁移。

完善 `GET /api/logs/{upload_id}/download`，通过 `type` 支持四种下载：`file&file_id=...` 下载单个解析日志，`batch` 下载全部解析日志 ZIP，`original` 下载用户最初上传的文件 ZIP，`results` 下载包含 `results.csv`、`data.json`、`report.md` 的分析结果 ZIP。单文件使用标准 HTTP Range，可断点续传并返回 `206`；不传 `type` 时保持原兼容行为，有 `file_id` 等同 `file`，否则等同 `batch`。ZIP 均按请求实时流式生成，不在服务器留下临时导出文件，因此无需额外清理任务。

新增 PostgreSQL 集成自动化测试，使用真实数据库、HTTP 路由和临时磁盘文件覆盖四类下载、Range、旧参数兼容、访问隔离、AI 聚合状态、通知终态去重、通知开关、单条/全部已读、负责人及备注事件和 SSE 推送。测试发现并修复 `AddResultComment` 同一参数在 `VARCHAR` 与 `TEXT` 字段间类型推断冲突导致的 `SQLSTATE 42P08`；备注作者参数现显式转换为 `text`，失败时同时写入后端错误日志。

## 822 调整（2026-08-22）
### AI 单独重试

新增 `POST /api/tasks/{task_id}/agent-retry`。接口只允许有权限访问且规则解析已完成的任务调用；服务端只清理文件级 AI 结果和任务级 AI 总览，保留原始日志和 `parse_results`，然后将已有命中结果重新加入 AI Worker 队列。AI 重试会递增结果执行代次，旧的 AI Worker 响应无法写入当前代次。新增迁移 `031_agent_retry_state.sql` 保存 AI 重试排队标记。接口返回 `202`，规则解析未完成时返回 `409`，AI 未配置时返回 `503`。

### 采集上传人自动注册与日志归属

采集端创建上传会话时，后端继续使用飞书 `tenant_access_token` 校验 `uploader_email`，并取得用户的 `OpenID、姓名、邮箱`。校验成功后通过 `UpsertCollectorIdentity` 将用户写入或更新 `logmaster_api.users`；因此飞书目录中存在但本地数据库尚未登记的用户会自动注册。

对内置或配置的采集端认证上传，后端还会幂等写入 `user_collected_upload_sessions`，把上传会话授权给经过校验的用户。上传会话的 `created_by_open_id` 仍保留采集端身份，保证采集端后续上传和关闭会话的权限不受影响；用户登录后通过现有日志查询、任务查询和结果查询权限逻辑，直接在自己的日志记录中看到这些采集日志。重复使用 `client_request_id` 时必须仍是同一个上传人，否则返回 `409`，避免借用幂等请求获取他人会话。普通网页用户提交邮箱不会触发该自动授权。

本次未修改前端和采集端代码、请求字段或接口路径。

## 822 补充：解析任务取消（2026-08-22）

新增 `POST /api/tasks/{task_id}/cancel`，仅允许任务创建者或已获采集日志访问权的用户调用。`queued` 任务立即进入 `cancelled`；`running` 任务清除租约并在当前文件处理边界停止。已完成或失败任务返回 `409`，重复取消已取消任务幂等返回 `202`。取消不会删除原始上传文件、已写入的解析结果或运行日志；任务和上传记录均保留 `cancelled` 状态，便于审计。新增迁移 `032_task_cancellation.sql`，扩展任务和上传状态约束。

### 原始日志全文搜索

新增 `GET /api/logs/{upload_id}/search`。接口复用日志访问权限，支持 `file_id`、`keyword`、`case_sensitive`、`page` 和 `page_size` 参数，返回命中总数以及文件 ID、相对路径、行号和原始行内容。单页最多返回 500 条，关键字最长 1000 个字符；不修改前端和采集端代码。

### 原始日志下载

新增 `GET /api/logs/{upload_id}/download`。初始版本传入 `file_id` 时直接下载单个日志文件，不传时以流式 ZIP 下载该上传批次的全部解析日志文件；823 已扩展为四种下载类型，完整契约见上方“解析结果和报告下载”。

### 中文失败提示与解压密码

上传会话、文件上传、压缩包解压和规则解析失败会通过 API `message`、任务 `error_message` 和运行日志返回中文错误描述。新增 `033_archive_passwords.sql` 和管理员接口：`GET/POST /api/admin/archive-passwords`、`DELETE /api/admin/archive-passwords/{id}`。普通管理员拥有现有 `keywords` 权限即可维护密码；列表只返回掩码。解析 ZIP 时按管理员配置密码和内置默认密码依次匹配，未配置密码时仍兼容原默认密码。

### 异常结果状态

新增 `PATCH /api/results/{id}/status`，状态枚举为 `pending`（待确认）、`confirmed`（已确认）、`false_positive`（误报）、`fixed`（已修复）、`closed`（已关闭）。接口校验结果访问权限，保存状态修改人和时间；新增迁移 `034_result_status.sql`。

### 异常结果备注

新增 `POST /api/results/{id}/comments` 添加备注，支持可选缺陷单号 `defect_id`；新增 `GET /api/results/{id}/comments` 查询历史备注。备注保留创建人和时间，只有结果有权访问者可以读写。新增迁移 `035_result_comments.sql`。

### 异常结果负责人

新增 `PUT /api/results/{id}/assignment`，请求体为 `{ "assigned_to": "用户 open_id" }`；传空字符串可取消分配。后端校验用户存在和结果访问权限，新增迁移 `036_result_assignment.sql`。

### 任务分析对比

新增 `GET /api/analysis/compare?baseline_task_id=...&current_task_id=...`。按文件路径、规则名称和命中文本聚合异常，返回 `new`、`resolved`、`persistent`、`increased`、`decreased` 五类结果，并校验两个任务的访问权限。

### 任务服务端分页筛选

增强 `GET /api/tasks`，新增 `page`、`page_size`、`status`、`project`、`version` 和 `sort` 参数。`sort` 支持 `updated_at`、`errors`、`oldest`，默认按创建时间倒序；响应新增当前页信息，旧调用不传筛选参数仍兼容。

## 821 调整（2026-08-21）

### 持久化解析任务队列（仅修改后端）

本次开始实现服务端任务调度基础设施，**没有修改前端和采集端代码**。上传接口完成文件落盘后不再为每个上传直接启动独立 Goroutine，而是由 PostgreSQL 中的 `parse_tasks` 作为持久化队列，由受控 Worker 领取并执行“准备/解压”和“规则解析”阶段。

新增迁移 `030_persistent_parse_queue.sql`：

- `parse_tasks` 增加 `phase`、`priority`、`attempt_no`、`worker_id`、`run_token`、租约和心跳字段；
- 新增 `parse_task_attempts`，保存每次 Worker 执行的代次、令牌、状态和错误；
- 使用 `FOR UPDATE SKIP LOCKED` 领取任务，避免多个后端实例重复处理同一任务；
- Worker 租约默认 90 秒，服务重启或 Worker 异常后，租约过期的任务可被其他 Worker 接管；
- 达到 `MAX_PARSE_ATTEMPTS` 后才将任务标记为 `failed`，不会无限重试。

新增环境变量：

```text
MAX_PARSE_WORKERS=2
MAX_PARSE_ATTEMPTS=3
```

默认最多同时执行 2 个准备/解析任务。任务结果写入、进度更新和完成状态都校验当前 `run_token`；文件级 AI 结果与任务级 AI 总览同时校验 `attempt_no`，旧执行代次不能污染接管后的新结果。当前阶段只提供调度基础设施，尚未新增重试、取消 HTTP 接口；这些接口将在队列基础上逐项实现。

### 任务重新解析接口（仅修改后端）

新增 `POST /api/tasks/{task_id}/retry`。接口只允许任务创建者或已获得采集日志访问权的用户对 `failed` 任务调用；服务端在事务中将任务和上传记录重新置为 `queued`，清除旧错误和租约，并设置人工重试标记后返回 `202`。规则解析会从持久化上传目录重新开始，历史执行代次不重置。同一次人工重试已在队列中时重复调用仍返回 `202`，不会产生第二个任务；初始排队、解析中或已完成任务返回 `409`。人工重试可以显式绕过自动租约接管次数上限，但仍受 Worker 并发控制。

### 对现有调用方的影响

- `POST /api/logs/upload` 和采集端上传接口路径、请求字段、响应结构不变；成功响应仍为 `202` 和 `status=queued`。
- `GET /api/tasks`、`GET /api/tasks/{task_id}` 的查询方式不变；对外任务状态继续使用现有 `queued/parsing/completed/failed`，内部 `parse_tasks` 才使用 `running`，取消状态将在后续任务取消功能中增加。
- 后端启动时会自动执行迁移并恢复未完成任务；不需要前端或采集端增加轮询之外的调用。
- 解压准备阶段不再依赖内存中的上传参数，服务重启后可以从上传存储目录重建待处理文件列表。

### 任务级 AI 总览（仅修改后端）

本次新增任务级 AI 聚合分析，**没有修改前端和采集端代码，也没有新增采集端字段**。现有的文件级 AI 分析全部完成后，后端在同一个 AI worker 队列中追加一个任务级聚合任务，将已有文件摘要和诊断结论合并为：

- 整个上传任务的总体结论；
- `critical/high/medium/low/unknown` 风险等级；
- 去重后的主要风险、证据、影响文件和置信度；
- 可执行的后续排查建议。

任务级聚合只使用已经生成的文件级 `summary` 和 `findings`，不再次读取或发送原始日志。一次聚合最多使用 50 个文件、100 条诊断，输入仍受 `llm_max_input_bytes` 限制，模型输出最多 4000 token，并计入当前用户的每日 AI token 配额。

新增迁移 `029_task_ai_overviews.sql`，结果持久化到 `logmaster_api.task_ai_overviews`。服务重启后自动执行迁移；聚合失败只记录失败状态，不影响关键字解析结果和原有文件级 AI 结果。

### 接口兼容方式

没有新增前端接口。原接口：

```http
GET /api/tasks/{task_id}/agent-results
```

在任务级总览生成后，会把它作为数组第一条返回：

- `file_path` 固定为 `任务级 AI 总览`；
- `log_file_id` 为 `0`，表示该记录不属于单个日志文件；
- `summary` 为整个任务的结论；
- `findings` 为聚合风险和一条汇总后的建议操作；
- 后续记录仍是原有的逐文件 AI 分析结果。

现有前端已经按数组遍历渲染 AI 结果，因此无需改前端即可展示。旧任务不会自动补算总览，重新上传并完成 AI 分析的新任务才会生成。

### 演示建议

准备一个包含两个以上日志文件、且存在不同类别异常的上传包。上传解析完成后打开现有“解析结果”页面，AI 总结区域的第一条应为“任务级 AI 总览”，下面仍保留逐文件诊断。演示时可说明：该功能不是重新把大日志送入模型，而是对已带证据的文件级诊断进行第二阶段聚合。

## 818 调整（2026-08-18）

### 采集端上传身份校验

采集端创建上传会话必须提交 `uploader_email`。后端先调用飞书通讯录 `contact/v3/users/batch_get_id` 校验邮箱是否属于当前企业且账号有效，再获取姓名和 `open_id`，并写入/更新 `users` 表及上传会话身份字段；`uploader_name` 为可选交叉校验字段。邮箱不属于企业、账号无效或姓名不匹配返回 HTTP 400。数据库迁移 `026_collector_identity_and_errors.sql` 增加会话身份字段。完成后需重启后端使迁移自动执行。

AI 分析完成后会写入 `logmaster_api.ai_usage` 记录 token 用量。新增迁移 `027_ai_usage_permissions.sql`，补齐该表及 `ai_usage_id_seq` 的数据库权限；重启后端执行迁移即可修复 `SQLSTATE 42501` 权限错误。

AI 命中日志采样不再简单取前 50 条，而是按规则/关键词分组轮询，尽量覆盖不同类型的命中；重复命中不会独占整个 AI 输入样本。

### 二、AI 分析结果接口（前端核心）

#### 2.1 接口

```
GET /api/tasks/{task_id}/agent-results
```

访问要求：飞书 Session（与现有 `results` 接口一致）。URL 未变。

#### 2.2 返回结构

返回一个数组，每条记录是一个「日志文件」的 AI 分析结果：

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "id": 1,
      "task_id": "uuid",
      "log_file_id": 3,
      "file_path": "items/1/extracted/system.log",
      "provider": "llm",
      "status": "completed",
      "summary": "本次日志整体运行正常，仅在存储链路出现间歇性 I/O 异常",
      "findings": [
        {
          "category": "storage",
          "severity": "error",
          "root_cause": "存储介质读写超时",
          "evidence": "第 120 行附近连续出现 input/output error",
          "impact": "可能导致录像写入失败并丢失片段",
          "suggestion": "检查 SD 卡健康状态、剩余空间与接触可靠性",
          "confidence": 0.9,
          "line_number": 120,
          "file_path": "items/1/extracted/system.log"
        }
      ],
      "error_message": "",
      "created_at": "2026-08-16T10:00:00Z",
      "updated_at": "2026-08-16T10:00:05Z"
    }
  ]
}
```

#### 2.3 记录级字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 记录 ID |
| `task_id` | string | 任务 ID |
| `log_file_id` | int | 日志文件 ID |
| `file_path` | string | 文件相对路径 |
| `provider` | string | `llm`（直连大模型）或 `http-agent`（外部 Agent） |
| `status` | string | `completed` 或 `failed` |
| `summary` | string | 该文件的 AI 总结 |
| `findings` | array | 该文件的诊断结论列表（见 2.4） |
| `error_message` | string | `status=failed` 时的错误信息 |
| `created_at` / `updated_at` | string | 时间 |

#### 2.4 findings 每项字段（重点：新增了 3 个字段）

| 字段 | 类型 | 是否新增 | 说明 |
|---|---|---|---|
| `category` | string | 否 | 分类：system / camera / gps / storage / sensor / network / recording / unknown |
| `severity` | string | 否 | 级别：warning / error / critical |
| `root_cause` | string | 否 | 可能原因 |
| `evidence` | string | 否 | 证据（引用的命中行或上下文） |
| **`impact`** | string | **是** | **影响**（该问题会造成什么后果） |
| `suggestion` | string | 否 | 建议 |
| `confidence` | number | 否 | 置信度 0~1 |
| **`line_number`** | int | **是** | **关联的原命中行号**（用于定位到结果表格里的某一行） |
| **`file_path`** | string | **是** | **关联的文件路径**（与 `line_number` 一起定位） |

> `line_number` 和 `file_path` 是为了让前端把「AI 解读」精确对应到规则解析结果表格里的某一条命中行。

#### 2.5 异步机制（重要）

AI 分析是**异步任务**：

1. 上传后，关键字规则解析**先同步完成**，`results` 接口立即可查（兜底，永远有结果）。
2. AI 结果在后台生成，**晚几秒到几十秒**才写入。
3. 所以 `agent-results` 接口在解析刚完成时**可能返回空数组**。

前端处理建议：

- 在解析结果页加载时先拉一次 `agent-results`；
- 若为空且任务状态已是 `completed`，可**延迟几秒再拉一次**（或轮询 1~2 次）；
- `provider=llm` 且 `status=completed` 表示 AI 成功，`status=failed` 表示失败（看 `error_message`）。

#### 2.6 AI 分析的输入上下文

AI 分析基于「命中行 + 上下文」。上下文以命中行为中心**对称截取**：命中行前 20 行 + 命中行 + 后 20 行（最多约 41 行），而不是只取命中行之前的日志。

送给模型的上下文中，每一行包含：

| 字段 | 说明 |
| --- | --- |
| `line_number` | 行号 |
| `timestamp` | 该行时间（若有） |
| `level` | 该行级别（error / warning / info / 空） |
| `content` | 该行内容 |
| `is_hit` | 是否为当前命中行（`true` 仅标记本条命中的命中行本身） |

> 说明：若上下文中还包含其它关键字命中，那是一个**独立的**解析结果，不会被合并；在本条命中的上下文里它只是一行普通日志（`is_hit=false`），但会带它自己的 `level`。

### 三、AI 限额（新增）

后端现在对 AI 分析做了**两级限额**，超出后自动降级为「只跑关键字规则」（不影响现有解析结果）。

#### 3.1 两个限额

| 限额 | 含义 | 默认值 |
|---|---|---|
| `max_tokens_per_file` | 单个日志文件允许的 AI 模型最大输出 token 数 | 20000 |
| `daily_token_quota` | 每个用户每天的 AI token 配额 | 1,000,000 |

- 每个文件都可进入 AI 分析；模型输出受 `max_tokens_per_file` 限制。
- 超 `daily_token_quota`：该用户当天后续文件跳过 AI，AI 结果记为 `failed` + `error_message` 提示 quota exceeded。

#### 3.2 管理员配置接口（前端需对接）

```
GET  /api/admin/ai-analysis-settings   # 查询，仅 super_admin
PUT  /api/admin/ai-analysis-settings   # 修改，仅 super_admin
```

`GET` 返回：

```json
{"code":0,"message":"success","data":{"max_tokens_per_file":20000,"daily_token_quota":1000000}}
```

`PUT` 请求体（与返回同结构，`updated_at` 可不传）：

```json
{"max_tokens_per_file":20000,"daily_token_quota":1000000}
```

字段约束：

- `max_tokens_per_file`：整数，1 ~ 1000000
- `daily_token_quota`：整数，`>= 0`，`0` 表示不限制

### 四、前端需要做的三件事

#### 4.1 解析结果页：AI 总结面板

- 数据源：`GET /api/tasks/{task_id}/agent-results`
- 展示：`summary`（文件级总结）+ `findings`（每条展示「可能原因 / 证据 / 影响 / 建议 / 置信度」）
- 处理异步：空结果时延迟重拉或轮询
- 处理失败：`status=failed` 时展示 `error_message` 或不展示 AI 面板

#### 4.2 每条日志「看上下文」旁：AI 解读

- 用 `findings` 里的 `line_number` + `file_path` 与结果表格当前行匹配
- 匹配到 → 在「看上下文」旁显示「AI 解读」入口，点击弹出该行的 AI 结论
- 匹配不到 → 不显示 AI 解读入口（说明该命中没有可用的 AI 分析结果）

#### 4.3 管理页：AI 限额设置

- 对接 `GET/PUT /api/admin/ai-analysis-settings`
- 两个输入框：`max_tokens_per_file`、`daily_token_quota`
- 仅超级管理员可见/可操作（与现有 `upload-capacity` 设置页同一权限级别）
- 表单校验：单文件 token 上限 1~1000000，配额 `>= 0`

### 六、配置项（部署侧，前端一般不需关心，仅供了解）

AI 功能由环境变量控制，未配置时 AI 分析不启用（不影响现有功能）：

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `LLM_API_BASE_URL` | 空 | OpenAI 兼容接口地址，空 = 禁用 AI |
| `LLM_API_KEY` | 空 | API Key |
| `LLM_MODEL` | `qwen-plus` | 模型名 |
| `LLM_TIMEOUT_SECONDS` | `120` | 单次分析超时 |
| `LLM_MAX_MATCHES` | `50` | 单次最多送入模型的命中条数，按规则/关键词分组轮询采样 |
| `LLM_MAX_INPUT_BYTES` | `200000` | 单次送入模型的最大输入字节数 |
| `AI_MAX_TOKENS_PER_FILE` | `20000` | 单文件 AI 模型最大输出 token 数（回退默认值） |
| `AI_DAILY_TOKEN_QUOTA` | `1000000` | 每用户每日 token（回退默认值） |

> 限额的最终生效值以管理后台配置为准（存数据库）；环境变量只是「管理员尚未配置时」的回退默认值。
